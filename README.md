# Задание 3. Библиотека метрик

Дедлайн – 29 ноября, 23:59 по Москве. 10 баллов.

## 1. Задача

Каждый запрос к сервису обновляет метрики: счётчик обращений растёт, длина очереди меняется, время ответа уходит в гистограмму. Обновляют их все рабочие потоки сразу, а Prometheus раз в несколько секунд забирает всё одним запросом и не должен останавливать запись. Напишите библиотеку, которая собирает метрики из потоков и отдаёт их текстом в формате Prometheus.

## 2. Контракт

### 2.1. Типы

Все классы находятся в пакете `edu.hse.concurrency.metrics`.

| Тип | Что это |
|---|---|
| `MetricId` | имя метрики и теги; проверяет имя, ключи тегов, `__`, `le` и `null` |
| `MetricType` | `COUNTER`, `GAUGE`, `TIMER` |
| `Counter` | `increment()`, `count()` |
| `Gauge` | `set(long)`, `get()` |
| `Timer` | `record(long)`, `snapshot()` |
| `TimerSnapshot` | `count`, `totalNanos`, `maxNanos`, `cumulativeBuckets` |
| `Registration` | подписка; `close()` |
| `RegistrationListener` | обработчик новой метрики |
| `MetricsRegistry` | интерфейс реестра |
| `MetricsRegistryImpl` | реализация |

Сигнатуры выданных типов и тесты менять нельзя. Свои классы добавлять можно. У `MetricsRegistryImpl` должен остаться публичный конструктор без аргументов: его использует `CounterBenchmark`.

`MetricId` уже проверяет имя, ключи тегов, префикс `__`, зарезервированный `le` и `null` в тегах. Тип метрики ему неизвестен. Всё, что зависит от типа, проверяет реестр: окончание имени и границы таймера.

### 2.2. Термины

**Ключ метрики** – имя и набор пар тег → значение. Порядок тегов не важен: два набора с одинаковыми парами дают один ключ.

**Новая метрика** – ключ, который регистрируется в реестре впервые.

**Бакет** – накопительный счётчик измерений таймера. Бакет с границей `B` содержит все измерения, не превышающие `B`: измерение ровно на границе попадает и в этот бакет, и во все бакеты с большими границами. Бакет `+Inf` содержит все измерения.

**Снимок таймера** – то, что возвращает `Timer.snapshot()`: число измерений, сумма, максимум и накопительные счётчики бакетов. Все значения снимка относятся к одному состоянию таймера.

### 2.3. Регистрация

| Метод | Что возвращает |
|---|---|
| `counter(name, tags)` | счётчик событий |
| `gauge(name, tags)` | текущее значение, например длину очереди |
| `timer(name, tags, upperBoundsNanos…)` | таймер с гистограммой задержек |

Метод возвращает метрику для ключа, регистрируя её при первом обращении. Для одного ключа повторный вызов возвращает тот же объект, в том числе когда ключ одновременно регистрируют несколько потоков.

Тип имени задаёт окончание: счётчик заканчивается на `_total`, таймер на `_seconds`, а gauge не может оканчиваться на `_total`, `_seconds`, `_bucket`, `_count` и `_sum`. Поэтому одно имя не может принадлежать двум типам: попытка зарегистрировать `requests_total` как gauge нарушает правило окончания и бросает `IllegalArgumentException`. У таймера с одним именем общие границы бакетов: второй вызов с другими границами не создаёт новую метрику, а бросает `IllegalArgumentException` и оставляет реестр в прежнем состоянии.

Реестр сохраняет копии тегов и массива границ. Если после вызова изменить исходные данные, уже зарегистрированная метрика не изменится.

### 2.4. Запись и чтение

| Метод | Поведение |
|---|---|
| `Counter.increment()` | прибавляет 1; начальное значение 0 |
| `Counter.count()` | возвращает число событий; после завершения всех записей значение точное |
| `Gauge.set(value)` | устанавливает значение `long`; допустимы и отрицательные |
| `Gauge.get()` | читает текущее значение; начальное значение 0 |
| `Timer.record(nanos)` | добавляет измерение в наносекундах; ноль допустим |
| `Timer.snapshot()` | снимает число измерений, сумму, максимум и накопительные счётчики бакетов |

Счётчик не теряет обновлений. Gauge хранит значение, которое установил последний вызвавший `set`.

Снимок таймера согласован: он соответствует результату целого числа вызовов `record`, ни один вызов не учтён частично. Поэтому `+Inf` всегда равен `count`: снимок с `count = 7` и `+Inf = 8` собран из разных состояний, и это ошибка. В `cumulativeBuckets` столько элементов, сколько границ, плюс один для `+Inf`. До первой записи число измерений, сумма, максимум и бакеты равны нулю. Полученный снимок не меняется. Переполнение `long` проверять не нужно, в том числе при суммировании.

### 2.5. Выгрузка

`scrape()` возвращает строку в текстовом формате Prometheus 0.0.4. Для каждого имени идёт одна строка `# TYPE` с типом `counter`, `gauge` или `histogram`, за ней все серии этого имени без временных меток. Других строк, в том числе `# HELP`, быть не должно. Порядок имён, серий и тегов произвольный. Бакеты одной серии идут по возрастанию границ, `+Inf` последним. Строка заканчивается переводом строки `\n`, пустой реестр возвращает пустую строку. [Формат выгрузки Prometheus](https://prometheus.io/docs/instrumenting/exposition_formats/#text-format-details)

Пример вывода для `request_seconds` с границей 1 000 000 нс и одной записью в 500 000 нс.

```text
# TYPE request_seconds histogram
request_seconds_bucket{route="/orders",le="0.001"} 1
request_seconds_bucket{route="/orders",le="+Inf"} 1
request_seconds_count{route="/orders"} 1
request_seconds_sum{route="/orders"} 0.0005
```

Границы и сумму выводите в секундах десятичной записью без экспоненты: целые без дробной части (`0`, `1`), дробные с минимальным числом знаков и без потери точности (`0.0005`, `0.000000001`). Значения счётчика и gauge выводите целыми числами. Максимум в `scrape()` не выводится, его отдаёт `snapshot()`. У счётчика и gauge имя в строке данных совпадает с именем метрики. У бакета тег `le` есть всегда, даже если других тегов нет; остальные фигурные скобки опускаются, когда тегов нет. В значениях тегов экранируйте обратную косую черту, кавычку и перевод строки как `\\`, `\"` и `\n`. Зарегистрированная, но ещё не обновлявшаяся метрика выводится с нулями.

`scrape()` можно вызывать одновременно с регистрацией и записью. Выгрузка содержит все серии, зарегистрированные до её начала; серия, появившаяся во время выгрузки, может в неё не попасть. Для каждого таймера берите один согласованный снимок, в котором `+Inf` равен `_count`. Разные серии разрешено читать в разные моменты.

### 2.6. Подписки

`onRegistration(listener)` подписывает на появление новых метрик и возвращает `Registration`. Вызов `close()` снимает подписку, повторный `close()` ничего не делает.

О новой метрике сообщает только поток, который зарегистрировал её первым. Он делает метрику видимой другим потокам, затем берёт текущий список подписок и вызывает каждый обработчик по разу, синхронно, до возврата из своего метода. Повторный запрос того же ключа уведомления не вызывает, как и сама подписка. Если подписку сняли после того, как уведомление попало в список на отправку, оно всё равно уйдёт.

Обработчики вызываются вне блокировок реестра, поэтому из обработчика можно снова обратиться к реестру. `RuntimeException` одного подписчика реестр перехватывает: остальные обработчики вызываются, регистрация сохраняется, наружу исключение не пробрасывается. Обработчик, который сам регистрирует новую метрику, получит уведомление о ней; защита от бесконечной рекурсии лежит на подписчике.

### 2.7. Требования

1. Методы реестра, метрик и `scrape()` можно вызывать из любого числа потоков одновременно.
2. Один ключ – один объект; у таймера с одним именем одни границы.
3. Счётчик не теряет обновлений, `Gauge.get()` возвращает последнее записанное значение.
4. Снимок таймера согласован: он соответствует целому числу вызовов `record`, `+Inf` равен `count`.
5. `scrape()` работает при одновременной регистрации, записи и чтении.
6. Подписка получает только новые метрики, `close()` идемпотентен, вызов реестра из обработчика не блокируется.
7. Программа не зависает и не бросает исключений, которых нет в контракте.
8. Регистрация и запись не ждут завершения `scrape()`.

## 3. Ограничения

### 3.1. Входные данные

| Что | Допустимо | Иначе |
|---|---|---|
| имя метрики, ключ тега | `[a-zA-Z_][a-zA-Z0-9_]*` | `IllegalArgumentException` |
| имя счётчика | заканчивается на `_total` | `IllegalArgumentException` |
| имя таймера | заканчивается на `_seconds` | `IllegalArgumentException` |
| имя gauge | без окончаний `_total`, `_seconds`, `_bucket`, `_count`, `_sum` | `IllegalArgumentException` |
| ключ тега | без префикса `__`; `le` зарезервирован | `IllegalArgumentException` |
| границы таймера | от 1 до 20 значений `long`, неотрицательные, строго возрастают | `IllegalArgumentException` |
| измерение таймера | `nanos ≥ 0` | `IllegalArgumentException` |
| любой аргумент, ключ и значение тега | не `null` | `NullPointerException` |
| значение тега | любая строка | допустимо |

Сначала проверяются аргументы на `null`, затем их значения. Некорректный вызов не меняет состояние реестра.

### 3.2. Средства

Для записи и чтения значений разрешены атомарные классы `java.util.concurrent.atomic` и `VarHandle`. Для реестра и подписок можно брать конкурентные коллекции, `synchronized` и локи JDK. Сторонние библиотеки допустимы в тестах и замерах.

В `increment`, `count`, `set`, `get`, `record` и `snapshot` запрещено:

- `synchronized`, локи, `wait`/`notify`, `LockSupport.park`, `sleep`, `yield`, `onSpinWait`, цикл опроса;
- ожидание в цикле, пока другой поток не закончит запись.

Повтор из-за неудачного CAS разрешён: он не ждёт конкретный поток.

## 4. Замер

В `CounterBenchmark` уже есть счётчики на `synchronized` и `AtomicLong`. Третий вариант использует ваш `Counter`. Каждый прогон измеряет обновления одного счётчика, общего для всех рабочих потоков.

```bash
./gradlew jmh -PjmhThreads=1
./gradlew jmh -PjmhThreads=4
./gradlew jmh -PjmhThreads=16
```

Запишите `Score ± Error` в `ops/s`, процессор, число ядер и версию JDK. Объясните, как число потоков повлияло на каждый вариант.

Один прогон занимает около полутора минут, все три – около пяти. Запускайте замеры на незагруженной машине: если ошибка в скобках больше десяти процентов от результата, повторите прогон.
