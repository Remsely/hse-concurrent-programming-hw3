## 1. Задача

Сервис считает запросы, хранит текущую длину очереди и записывает время ответа. Метрики обновляют потоки сервиса, а Prometheus периодически забирает их одним запросом. Напишите библиотеку, которая собирает эти данные и выдаёт их в текстовом формате Prometheus.

## 2. Контракт

### 2.1. Реестр

Все классы находятся в пакете `edu.hse.concurrency.metrics`. Реализуйте `MetricsRegistryImpl` и добавьте свои классы для метрик. Сигнатуры выданных типов и тесты менять нельзя.

| Метод | Результат |
|---|---|
| `counter(name, tags)` | Счётчик запросов или других событий |
| `gauge(name, tags)` | Текущее значение, например длина очереди |
| `timer(name, tags, upperBoundsNanos…)` | Таймер с гистограммой задержек |

Ключ метрики — имя и набор пар «тег → значение». Порядок тегов не важен. Для одного ключа повторный вызов возвращает тот же объект, в том числе при одновременной регистрации. У одного имени общий тип для всех наборов тегов, а у таймера с одним именем ещё и общие границы бакетов. Вызов с другим типом или границами бросает `IllegalArgumentException` и оставляет реестр в прежнем состоянии.

Реестр сохраняет копии тегов и массива границ. Изменение исходных данных после вызова не меняет уже зарегистрированную метрику.

### 2.2. Запись и чтение

| Метод | Поведение |
|---|---|
| `Counter.increment()` | Прибавляет 1. Начальное значение — 0 |
| `Counter.count()` | Возвращает число событий. После завершения всех записей значение точное |
| `Gauge.set(value)` | Устанавливает значение `long`. Допустимы и отрицательные значения |
| `Gauge.get()` | Читает текущее значение. Начальное значение — 0 |
| `Timer.record(nanos)` | Добавляет измерение в наносекундах. Ноль допустим |
| `Timer.snapshot()` | Снимает число измерений, сумму, максимум и накопительные счётчики бакетов |

В конечный бакет входит каждое измерение, которое не превышает его верхнюю границу. Измерение на границе попадает и в этот бакет, и во все следующие. Последний бакет, `+Inf`, включает все измерения. До первой записи число измерений, сумма, максимум и значения бакетов равны нулю.

Поля одного `TimerSnapshot` соответствуют одному состоянию таймера. Например, `count = 7` и `+Inf = 8` означают, что снимок собран из разных состояний. После получения снимок не меняется. Тестовые данные укладываются в `long`, в том числе при суммировании.

### 2.3. Выгрузка

`scrape()` возвращает строку в текстовом формате Prometheus 0.0.4. Для каждого имени выведите одну строку `# TYPE`, затем все его серии без временных меток. Порядок имён и тегов произвольный. Бакеты одной серии идут по возрастанию границ, `+Inf` — последним. Строка заканчивается переводом строки `\n`, пустой реестр возвращает пустую строку. [Формат выгрузки Prometheus](https://prometheus.io/docs/instrumenting/exposition_formats/#text-format-details)

Пример вывода для `request_seconds` с границей 1 000 000 нс и одной записью в 500 000 нс.

```text
# TYPE request_seconds histogram
request_seconds_bucket{route="/orders",le="0.001"} 1
request_seconds_bucket{route="/orders",le="+Inf"} 1
request_seconds_count{route="/orders"} 1
request_seconds_sum{route="/orders"} 0.0005
```

Выводите границы и сумму в секундах. Максимум доступен через `snapshot()`. У счётчиков и gauge имя в строке данных совпадает с именем метрики. Скобки `{}` опускаются, когда тегов нет. В значениях тегов экранируйте обратную косую черту, кавычку и перевод строки как `\\`, `\"` и `\n`.

Можно вызывать `scrape()` одновременно с регистрацией и записью. Для каждого таймера берите один согласованный снимок, в котором `+Inf` равен `_count`. Разные серии разрешено читать в разные моменты.

### 2.4. Подписчики

`onRegistration(listener)` подписывает на появление новых метрик и возвращает `Registration`. Вызов `close()` снимает эту подписку. Повторный `close()` ничего не делает.

О создании ключа сообщает только поток, который впервые его зарегистрировал. Он публикует метрику, берёт текущий список подписок и вызывает каждую один раз. Повторный запрос того же ключа и сама подписка уведомлений не вызывают. Снятие подписки не отзывает уведомление, если оно уже попало в список на отправку.

Вызывайте обработчики вне блокировок реестра. Подписчик может обратиться к реестру из обработчика. `RuntimeException` одного подписчика не мешает остальным и не отменяет регистрацию.

## 3. Ограничения

| Что | Допустимо |
|---|---|
| Имя метрики и ключ тега | `[a-zA-Z_][a-zA-Z0-9_]*` |
| Имя счётчика | Заканчивается на `_total` |
| Имя таймера | Заканчивается на `_seconds` |
| Имя gauge | Без окончаний `_total`, `_seconds`, `_bucket`, `_count`, `_sum` |
| Ключ тега | Без префикса `__`, имя `le` зарезервировано |
| Границы таймера | От 1 до 20 значений `long`, неотрицательные, строго возрастают |
| Измерение таймера | `nanos ≥ 0` |

При `null`, включая ключ или значение в карте тегов, бросайте `NullPointerException`. При остальных нарушениях — `IllegalArgumentException`. Некорректный вызов не меняет состояние.

Для записи и чтения значений используйте атомарные операции JDK. В `increment`, `count`, `set`, `get`, `record` и `snapshot` запрещены `synchronized`, замки и ожидание в других потоках. Цикл CAS разрешён. Для реестра и подписок разрешены конкурентные коллекции и синхронизация JDK. Сторонние библиотеки допустимы в тестах и замерах.

## 4. Замер

В `CounterBenchmark` уже есть счётчики на `synchronized` и `AtomicLong`. Третий вариант использует ваш `Counter`. Каждый прогон измеряет обновления одного счётчика, общего для всех рабочих потоков.

```bash

./gradlew jmh -PjmhThreads=4
./gradlew jmh -PjmhThreads=16
```
